# Campus Hub: вход и профиль студента

## Установка обновления

1. Остановите Expo (Ctrl+C). Для резервной копии сохраните прежние App.tsx и src вне папки проекта.
2. Скопируйте App.tsx и папку src из этого архива в существующий C:\Users\blenz\CampusHub с заменой совпадающих файлов. Объедините папки, не удаляйте старую src: архив содержит только обновление.
3. Выполните:

```powershell
cd C:\Users\blenz\CampusHub
npm install firebase@^12
npx expo install @react-native-async-storage/async-storage
npx tsc --noEmit
npx expo start --clear
```

Откройте приложение в Expo Go. В архиве нет package.json: команды обновят существующие package.json и package-lock.json.

## Первый вход

- Нажмите «Нет аккаунта? Зарегистрироваться».
- Введите имя, настоящий email, пароль и повтор пароля.
- Пароль: минимум 8 символов, латинская заглавная и строчная буквы, цифра.
- После регистрации нажмите «Отправить письмо».
- Откройте ссылку в почте (проверьте также спам).
- Вернитесь в приложение и нажмите «Я подтвердил email».
- После подтверждения появятся пять вкладок, включая «Профиль».

В Firebase Authentication → Settings → Password policy задайте те же требования к паролю (минимум 8, upper/lowercase, numeric), режим Require. Клиентская подсказка сама по себе не задаёт серверную политику. Email enumeration protection оставьте включённой. В Authentication → Users можно увидеть созданный тестовый аккаунт. Пароль там не отображается.

## Что реализовано

Регистрация и вход Firebase; проверка полей; показ/скрытие пароля; восстановление и смена пароля по письму; подтверждение email перед доступом к учебному интерфейсу; имя профиля; восстановление сессии после перезапуска; выход; сообщения при неверных данных, потере сети и частых попытках.

Email выступает логином. Имя хранится в Firebase Authentication displayName. Статус «студента» — название учебного профиля, не проверка зачисления в университет.

## Задачи и ограничения учебного примера

Каждый UID получает отдельную SQLite-базу на устройстве. После выхода состояние и навигация сбрасываются. Новый пользователь получает пустой список; после повторного входа прежнего пользователя его задачи возвращаются. Облачной синхронизации задач нет. Исходная база campushub.db (до входа) не изменяется и не присваивается автоматически первому аккаунту: её задачи не отображаются в новых профилях.

SQLite не зашифрована. Разделение по UID предотвращает смешивание списков в интерфейсе, но не является защитой от чтения файлов на скомпрометированном устройстве. Подтверждение email здесь ограничивает клиентский учебный интерфейс. При добавлении облачных данных потребуются серверные правила доступа по request.auth.uid и, при необходимости, email_verified.

Пароль не записывается в SQLite, AsyncStorage или логи. Firebase SDK сохраняет данные сессии в AsyncStorage; это не зашифрованное хранилище. Для приложения с чувствительными данными требуется отдельная оценка хранения сессий и серверной защиты. Смена пароля/отзыв доступа не обеспечивают немедленную офлайн-блокировку локальной базы.

В src/services/firebase.ts уже стоят предоставленные клиентские настройки CampusHub. Они не являются ключом сервисного аккаунта. Студентам для собственных проектов следует создать отдельный Firebase-проект и заменить конфигурацию; административные ключи и пароли в Git не помещают.

## Проверка перед записью

1. Пустые поля, неправильный email, короткий пароль, несовпадающий повтор: сообщения без перехода.
2. Регистрация с действующей почтой; повторная регистрация; проверка письма и вход после подтверждения.
3. Неправильный пароль → общее сообщение без раскрытия существования аккаунта.
4. Восстановление пароля → письмо, новый пароль, успешный вход.
5. Имя сохраняется после выхода/входа.
6. Аккаунт A: создать задачу → выйти → аккаунт B: список пустой → вернуться в A: задача на месте.
7. Перезапуск Expo Go: сессия восстанавливается.
8. Отключить интернет при входе: понятная ошибка, кнопка снова доступна после завершения запроса.

```powershell

git diff --cached
git commit -m "Add Firebase authentication and student profile"

```

Сначала скопируйте INSTALL_AUTH.md в корень проекта. Если репозиторий ещё не создан, следуйте docs/VIDEO_GITHUB.md из первоначального комплекта. При записи экрана приостановите запись на вводе личного пароля. Не показывайте реальный список пользователей Firebase студентам; используйте тестовые данные.
